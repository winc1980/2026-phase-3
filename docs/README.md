# Phase 3 の進め方

## チーム開発

チームで協力して開発を行っていきます。

## ふだん：家/部室で開発

### タスクを取る
チームにとって優先順位が高いタスクの中で、自分にできそうなものを選びます。
同時に進めるのは1個だけです。難しすぎたり、他のタスクを待つ必要があって詰まった時は、すぐにチームメイトに相談しましょう。

### 実装する
自力で調べて、頑張って実装してください。AIに相談してもOKです。
それでも分からないときは、チームメイトに聞くか、学習会メンターをメンションして相談してください。必ず力になります。

### PR(プルリクエスト)を出す
実装を終えたら、まずは動作確認をします。タスクの要件を満たす動作が確認できたら、レビューしてくれるチームメイトのために説明文を書きましょう。

レビューで指摘を受けたら、修正します。指摘がたくさんあっても、落ち込まなくて大丈夫です。大学の試験と違って、ミスがあっても直して再提出できます。全部直せば100点です。

### PRを確認してマージする
チームメイトのPRをレビューします。AIと一緒にやってもOKです。動作確認をして、おかしなところがあれば、コードの具体的な場所を特定して指摘します。実装した本人には気付かない間違いというのは誰にでもあるものなので、遠慮せずに指摘してあげてください。 

すべての指摘の修正を見届けたら、mainブランチにマージできます。これにて、タスク完了です。お疲れ様でした。

# AI利用ポリシー
今回から、AIの利用を条件付きで容認します。

### 条件
- コード生成をさせるのではなく、相談相手として利用すること：[AIメンター](#AIメンター)

AIメンターとしてAIを使う場合でも、**最終的にコードがもたらす結果に責任を持つのは自分自身**だということを忘れないでください。 
AIが教えてくれたコードが何をしているのかを理解し、**チームメイトに説明できるように**しておいてください。 
誰も理解していないコードが積み上がっていくことがないように、チームメイトとよく相談して、計画的に運用してください。

## AIメンター
2種類の方法を案内します。どちらでも全く問題ありません。

AIに課金していない人：[ChatGPTメンター.md](ChatGPTメンター.md)
無料版のChatGPTに自分のレポジトリの情報を与えて相談する方法を案内します。

AIに課金している人：このまま使えます
レポジトリのAGENTS.mdが自動的に適用されます。 
事前導入されているAIメンター設定を使用する場合は、[AIメンター.md](/AI_mentor.md)のファイルパスを渡してあげてください。

# この学習のゴール

### プロジェクト経験：開発全体を見通す視点を身に付ける
- 開発プロジェクト全体を経験すること
- チームでタスクとスケジュールの状況を共有し、計画的に開発を進めること
- 春休みの時点で、実ユーザーを抱えるプロジェクトに参加できる状態になること

### エンジニアとしての自立：自走力をつける
- issue作成->優先順位付け->issue着手->PR提出->レビュー->マージまでの一連の流れを回せるようになること
- 分からないことを自分で調べて解決できるようになること
- AIを活用し、うまくいった経験、いかなかった経験の両方から教訓を得ること

# 環境構築

1. 代表者がこのレポジトリをフォークする
2. チームメンバーにcontributor招待を送る,もしくはgithub上のタグ"winc-2026"のユーザーに書き込み権限を与える
3. チームメンバーがgit cloneをする
4. README.mdとAGENTS.mdにプロジェクトのコンセプトを書き込む
5. 使用する技術に合わせた環境構築：2週目からそれぞれのプロジェクトの事情に合わせて進めていきます
