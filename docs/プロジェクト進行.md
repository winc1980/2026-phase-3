# マイルストーン
マイルストーンとは、いつまでに何を達成するかの目標であり、開発の道しるべです。
phase3では、月ごとのLT会をマイルストーンの目安にします。

githubには、専用の機能"milestones"があります。自分たちのプロジェクトの内容に合わせて書き込んでみてください。

## MVP開発：最小限の実用性を提供する
最低限使えるものをとにかく早く作ろうという考え方です。
milestone設定では、この考え方を意識してください。
例えば、以下のように設定できます。(文言は例。内容は概ねこのくらいのペースになると想定しています)
10月末：最低限の見た目を作ること(モック)
11月末：最低限の動作を作ること(プロトタイプ)
12月末：最低限、サービスを提供できていること(MVPリリース)
(後期試験期間を挟んで)
2月末：最低限、外部のユーザーに使ってもらえる状態になっていること(ベータリリース)

どれも、最低限を作るには何が必要かを基準に考えてください。

# タスク
チームが次に何に取り組もうとしているか、をタスクとして言語化しましょう。
タスクはgithubのissueにすることで、誰でも着手可能な状態にできます。

## 優先順位を付ける
やることに優先順位を付けなければ、開発を期限内に終わらせることはできません。

ここではMoSCoW分析を紹介します。
Must/必須
should/作るべき
could/あるとよい
won't/いらない
タスクを以上の4つに分けます。
mustから着手し、mustがすべて終わって時間が余れば、should、couldへと広げていきます。

このタスク整理をマイルストーンごとに行うことをお勧めします。将来必要になるかもしれないものの中には、今のマイルストーンではwon'tでいいものもあるかもしれません。今、必要なものに集中することが大事です。

## タスクの依存関係を可視化する
一部のタスクには、前提として別のタスクが終わっていないと着手できないものがあります。このような依存関係を可視化して、依存関係の先頭にあるタスクに最優先で取り組むようにしましょう。


## タスクを分割する
タスクの完了に必要な作業量、技術的難易度は、タスクによって様々です。
実際にチームで作業に取り組む前に、次のもくもく会までの1週間でできる大きさに分割しましょう。
作業時間3～5時間、コード100～300行程度くらいが目安です。
さらに小さくて取り組みやすいタスク(good first issue)もあると良いでしょう。
小さなタスクでも、やりきったことが成果として可視化されると達成感があります。

全員が何かしらタスクに取り組めている状態が理想です。


# コミュニケーション
チーム内で常に情報を共有しましょう。
github、discord、対面の3つの場をうまく使い分けましょう。
githubにはソースコードとタスクが置かれます。作業状況は、ここを見れば。
discordでは、タスクに取り組む中でうまくできたこと、いかなかったこと、チームのみんなと一緒に考えたいことなどを共有しましょう。
対面は一週間に一回の貴重な場です。自分たちが何を作ろうとしているのか、チームとしてどこに向かっていきたいのかをよく話し合って、開発計画を立てていきましょう。

## discord

フォーラムは、各タスクや個別の議題ごとにスレッドを分けて話し合うのに向いています。
